# Workflows

Argo Workflows' controller in its own namespace, managing `orchestration` only, and the template that dispatches a job to the worker ([ADR 0029](../decisions/0029-argo-workflows-in-its-own-namespace-and-the-ui-on-the-operators-machine.md), [ADR 0030](../decisions/0030-how-a-job-reaches-the-worker.md)). The procedure is the [workflows runbook](../runbooks/workflows.md).

Status: **tested** on the live system on 2026-10-21. `W.1` to `W.10` failed on absence before the install, on 2026-10-20, and passed at 04:24 UTC after it. `W.11` failed on absence before its secret existed and passed at 15:26 UTC, and its parser gives another value for a secret with no token, another type, or another account ([worklog](../worklogs/0003-toolchain-integration.md#installed-argo-and-the-first-workflows)). `W.12` passed in its first check run, on 2026-10-25 from 18:24 to 18:32 UTC. It failed with `1 27` while `argo-operator` was given `patch` on config maps in `orchestration`, and passed again after ([worklog](../worklogs/0005-netbox-target-and-exercise-1.md#w12-fails-on-a-broken-input)). `W.7` failed on 2026-10-26 with `0 1`, in a copy of the script that asked kubectl for a verb that does not exist, where before the change for #173 it passed ([worklog](../worklogs/0005-netbox-target-and-exercise-1.md#the-counting-checks-fail-on-a-broken-command)).

## Limits

- **`W.9` compares what the API server gives back.** If the server adds defaults to the stored spec, `W.9` fails on a correct template. It passed on its first run on the cluster, on 2026-10-21, so the server added none to this template. A change to Argo's defaults can still break it.
- **`W.2` reads the digest containerd used.** The images are pulled by the digest of their multi-platform index, and the pod's image ID showed that digest on the cluster on 2026-10-21.
- **Argo's offline linter does not check parameter references.** In the pipeline it fails on an unknown field and on a template that names a missing one, both seen on 2026-10-20. A misspelled `{{workflow.parameters...}}` passes it.
- **`W.11` reads that the secret holds a token, not that the token works.** A workflow that starts shows that.
- **`W.12` asks the accounts of three namespaces.** Three of the 40 accounts in `kube-system` can change config maps in `orchestration`, asked on 2026-10-25: Kubernetes' garbage collector (update, patch, delete), its namespace controller (delete), and its root certificate publisher (create, update). They are part of the K3s server on the orchestrator, and `W.12` does not ask them. A new account in the three namespaces changes the count, and the check fails until its expected value moves.
- **No check reads what a workflow did.** The round trip, the cancel, and the refused submissions are procedure steps in the [runbook](../runbooks/workflows.md), because they start jobs.
