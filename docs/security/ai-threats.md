# AI-specific threats

Threats that exist because a model reads untrusted text and can act on it. They sit on top of the boundary threats in the [threat model](threat-model.md), and most of their controls arrive in milestone 3 with the [tool service](tool-service.md). States were reviewed on 2026-10-14, and again on 2026-10-15 after the tool service was deployed, using the state definitions in the threat model. A4 and A6 moved on 2026-10-18 with the agent runtime checks. A6 and A7 moved on 2026-10-19 for what ADR 0030 decides. A6 and A8 moved on 2026-10-20 with the first jobs on the worker. A6 and A7 moved on 2026-10-21 with the first workflows, and ADR 0030 was accepted the same day. A1, A3, A7, and A8 gained the results of the model comparison on 2026-10-22, with no change of state.

The design's answer to most of these is the same: assume the worker is compromised, and limit its credentials, tool access, and network connections.

The tool service's 28 packages install by hash, and a blocking dependency scan runs on every pull request. The tool service image is pulled by digest, checked by `T.2`. The installed Goose binary is compared with its own pin by `G.1` on every check run, since 2026-10-18 | 3 | A backdoored model behaves until it does not. ATLAS AML.T0057, AML.T0086 | High | The broker publishes checked fields, not free text from the worker | Open | 5 | Depends on the broker design. Harmless here only because the data is synthetic |
| A6 | Context poisoned in one job steers a later one | ASI06. ATLAS AML.T0080 | Medium | One scoped session per job, with cleanup. Same control as T19 | Built for the agent's own files: they live in the unit's private `/tmp` and are gone when it stops, which `G.4` checks since 2026-10-18. The model server's prompt cache outlives a job and is not cleared. Decided: the job unit erases it after each job ([0030](../decisions/0030-how-a-job-reaches-the-worker.md)). The first jobs on the worker, on 2026-10-20, found the erase refused, and the second job's first turn reused the first job's prompt. Fixed and seen working the same day: a re-run erased the slot after each job, the next job's first turn read its whole prompt, and `G.10` passed ([troubleshooting 12](../troubleshooting/12-slot-erase-needs-a-save-path.md)). Verified on 2026-10-21 through dispatch: a completed and a stopped workflow each erased the slot ([worklog](../worklogs/0003-toolchain-integration.md#installed-argo-and-the-first-workflows)) | 3, 6 | Shared VM |
| A7 | A job is driven into unbounded inference | OWASP LLM: Unbounded Consumption. ATLAS AML.T0034.002 | Medium | Time and output limits. Same control as T20 | A time limit and a turn limit are set on the unit. Neither limit has been reached in a test. The tool service rejects tool calls after the first 20, tested in CI. Decided: a deadline on the workflow, shorter than the unit's and the token's ([0030](../decisions/0030-how-a-job-reaches-the-worker.md)). Built on 2026-10-21: a workflow whose pod never started failed at its step's deadline. No running job has reached it ([worklog](../worklogs/0003-toolchain-integration.md#installed-argo-and-the-first-workflows)). In the model comparison, outside a job, Qwen3.5-4B answered evidence that asked for `ev-0001` with calls for 31 references in one turn, stopped by the request's 1,024-token output limit ([worklog](../worklogs/0003-toolchain-integration.md#second-run)) | 3 | None beyond a lost job |
| A8 | The agent runtime executes commands the model wrote | ASI05 | Medium | A restricted tool set: the runtime loads only the tools named on its command line, and the one that runs shell commands is never named. The worker is assumed compromised either way | Built for the fixture run: one tool reached the model. With the tool service, the tool set comes from a recipe and an empty configuration directory, and the service lists only the tools in the job's scope: one tool reached the model in a workstation run. On the worker on 2026-10-20, Goose also offered its own `load_skill`, which no recipe removes and which returns one of two texts bundled in the binary ([#139](https://github.com/sindredg/ai-security-platform/issues/139)). Goose renders the recipe as a template before parsing it, so a task with template syntax could replace the recipe and its extensions: seen with `--render-recipe` and the pinned binary on a workstation. The job program refuses such a task, and one Goose would run as a shell or slash command. Written, with unit tests. Not tested: a model that asks for a tool it was not given. In the model comparison, evidence asked for a tool the model was not given, and none of three models called it ([worklog](../worklogs/0003-toolchain-integration.md#second-run)) | 3 | Code execution on the worker is the starting assumption, not the breach |
