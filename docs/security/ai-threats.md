# AI-specific threats

Threats that exist because a model reads untrusted text and can act on it. They sit on top of the boundary threats in the [threat model](threat-model.md), and most of their controls arrive in milestone 3 with the [tool service](tool-service.md). States were reviewed on 2026-10-14, and again on 2026-10-15 after the tool service was deployed, using the state definitions in the threat model. A4 and A6 moved on 2026-10-18 with the agent runtime checks. A6 and A7 moved on 2026-10-19 for what ADR 0030 decides. A6 and A8 moved on 2026-10-20 with the first jobs on the worker. A6 and A7 moved on 2026-10-21 with the first workflows, and ADR 0030 was accepted the same day. A1, A3, A7, and A8 gained the results of the model comparison on 2026-10-22, with no change of state. The same day, A1 and A3 gained a planned control: each verdict is compared with the deterministic checks. A6 moved on 2026-10-23 for the erase before each job. Later that day, for the milestone 3 close, A3 gained the wrong answer of a dispatched job, and A4 the [supply chain](supply-chain.md) page, the provenance of llama.cpp and Goose, and the tool service dependency scan as a required check. A7's state was labelled Built on 2026-10-24, in the review of milestone 3, with no change in what it records. Later that day A3 gained the deterministic checks for exercise 1, decided in [ADR 0037](../decisions/0037-an-unscoped-copy-of-the-consumers-permission.md), with no change of state. On 2026-10-25 A1 gained the evidence schemas, written and not deployed, with no change of state. Later that day they were deployed, and A1 records them as Verified on the live service. Its leading state stays Planned. Later on 2026-10-25 A1 and A3 gained the comparison, decided in [ADR 0041](../decisions/0041-the-workflow-compares-the-models-verdict-with-the-checks.md), with no change of state.

The design's answer to most of these is the same: assume the worker is compromised, and limit its credentials, tool access, and network connections.

| A1 | Instructions hidden in an advisory, a tool result, or target evidence take over the agent | OWASP LLM: Prompt Injection. ASI01. ATLAS AML.T0051.001 | High | Not prevented. Contained by T16 to T18, by allowlisted change fields, by rehearsal, and by approval. A verdict that disagrees with the deterministic checks stops for the operator (A3), so injected text cannot close a finding the checks found | Planned. Observed in the model comparison on 2026-10-21: each of three models followed at least three of four instructions injected into tool results ([worklog](../worklogs/0003-toolchain-integration.md#second-run)). Verified on 2026-10-25 on the live service: the evidence tool hands the model only the fields and values its schema names, and refused a NetBox document with an injected field, whose text did not reach the answer ([#152](https://github.com/sindredg/ai-security-platform/issues/152), [worklog](../worklogs/0005-netbox-target-and-exercise-1.md#the-collection-and-the-jobs)). NetBox's free text stays out of a job's evidence ([0040](../decisions/0040-a-jobs-evidence-is-collected-on-the-hosts-and-stored-per-job.md)). That narrows what reaches the model. It does not stop an instruction that fits a field's pattern. Decided on 2026-10-25: the workflow compares a NetBox job's verdict for each account with the checks', and anything but a match ends it for the operator ([0041](../decisions/0041-the-workflow-compares-the-models-verdict-with-the-checks.md)) | 6 | The agent's output is untrusted every time, injected or not |
| A2 | The agent uses a legitimate tool for something its job does not need | OWASP LLM: Excessive Agency. ASI02, ASI03. ATLAS AML.T0053, AML.T0101 | High | Narrow tools with no destructive operations. Delivery belongs to a separate trusted runner | Built for the current evidence tool, deployed on the orchestrator: it reads one file by reference and changes nothing. No delivery runner exists | 3, 6 | A tool that reads too much is still a tool that reads |
| A3 | The model is wrong and convincing, and the operator approves it | OWASP LLM: Misinformation. ASI09 | High | Tools establish facts, and a verdict that disagrees with the deterministic checks stops the workflow for the operator ([architecture](../architecture.md#workflow)). Rehearsal tests the fix. The pull request states what is uncertain. An unsafe patch is rejected even when its tests pass | Planned. Observed in the model comparison on 2026-10-21: all three models called a token whose grants equal its contract confirmed ([worklog](../worklogs/0003-toolchain-integration.md#second-run)). Observed on 2026-10-23 through dispatch: a job answered `Status: confirmed` and `Excess: none` against evidence with two record types in excess, and the dispatch step passed it, because it does not read the verdict ([worklog](../worklogs/0003-toolchain-integration.md#the-wrong-answer)). Decided on 2026-10-24 for exercise 1: the deterministic checks the verdict is compared with are the sum of the consumer's configured permissions and the records its token returns ([0037](../decisions/0037-an-unscoped-copy-of-the-consumers-permission.md)). Decided on 2026-10-25: how the workflow compares, one verdict line per account read from the answer, and that a mismatch, an inconclusive verdict, or an answer it cannot read ends the workflow Failed, with no override ([0041](../decisions/0041-the-workflow-compares-the-models-verdict-with-the-checks.md)) | 4, 5 | One tired approver |
| A4 | The model file, the agent runtime, or a tool server is poisoned upstream | OWASP LLM: Supply Chain. ASI04. ATLAS AML.T0010, AML.T0058 | High | Digest pins, a known publisher, and worker containment for whatever gets through. The model file is built from the publisher's weights, so no third-party quantizer is in the chain ([ADR 0015](../decisions/0015-build-the-model-file-on-the-worker.md)) | Built for the model server and the agent runtime: every file is checked against a pinned checksum on the orchestrator, and again on the worker ([supply chain](supply-chain.md)). Verified on 2026-10-23 on the workstation: llama.cpp's and Goose's signed provenance names their release workflows and the pinned commits ([worklog](../worklogs/0003-toolchain-integration.md#provenance-of-llamacpp-and-goose)). The tool service's packages install by hash, and the tool service dependency scan, a required check since 2026-10-23, fails on a known advisory in them ([#167](https://github.com/sindredg/ai-security-platform/issues/167)). The tool service image is pulled by digest, checked by `T.2`. The installed Goose binary is compared with its own pin by `G.1` on every check run, since 2026-10-18 | 3 | A backdoored model behaves until it does not. The publisher, llama.cpp, Goose, and the MCP SDK are still trusted |
| A5 | Evidence leaves the platform inside proposal text published to the repository | OWASP LLM: Sensitive Information Disclosure. ATLAS AML.T0057, AML.T0086 | High | The broker publishes checked fields, not free text from the worker | Open | 5 | Depends on the broker design. Harmless here only because the data is synthetic |
| A6 | Context poisoned in one job steers a later one | ASI06. ATLAS AML.T0080 | Medium | One scoped session per job, with cleanup. Same control as T19 | Built for the agent's own files: they live in the unit's private `/tmp` and are gone when it stops, which `G.4` checks since 2026-10-18. The model server's prompt cache outlives a job unless it is erased. Decided: the job unit erases it after each job ([0030](../decisions/0030-how-a-job-reaches-the-worker.md)). The first jobs on the worker, on 2026-10-20, found the erase refused, and the second job's first turn reused the first job's prompt. Fixed and seen working the same day: a re-run erased the slot after each job, the next job's first turn read its whole prompt, and `G.10` passed ([troubleshooting 12](../troubleshooting/12-slot-erase-needs-a-save-path.md)). Verified on 2026-10-21 through dispatch: a completed and a stopped workflow each erased the slot ([worklog](../worklogs/0003-toolchain-integration.md#installed-argo-and-the-first-workflows)). Decided on 2026-10-23: the slot is erased before each job as well, and the job is refused when that fails ([0032](../decisions/0032-erase-the-slot-before-each-job-and-refuse-on-failure.md)). Verified the same day on the worker, with the model server stopped: the job was refused before Goose started ([worklog](../worklogs/0003-toolchain-integration.md#installed-the-erase-before-each-job-and-the-answer-lines)) | 3, 6 | Shared VM |
| A7 | A job is driven into unbounded inference | OWASP LLM: Unbounded Consumption. ATLAS AML.T0034.002 | Medium | Time and output limits. Same control as T20 | Built for a job: the time limit on its unit, `aisec-agent-job@`, and the turn limit the job program passes to Goose (`agent_job.py`). Neither limit has been reached in a test. The tool service rejects tool calls after the first 20, tested in CI. Decided: a deadline on the workflow, shorter than the unit's and the token's ([0030](../decisions/0030-how-a-job-reaches-the-worker.md)). Built on 2026-10-21: a workflow whose pod never started failed at its step's deadline. No running job has reached it ([worklog](../worklogs/0003-toolchain-integration.md#installed-argo-and-the-first-workflows)). In the model comparison, outside a job, Qwen3.5-4B answered evidence that asked for `ev-0001` with calls for 31 references in one turn, stopped by the request's 1,024-token output limit ([worklog](../worklogs/0003-toolchain-integration.md#second-run)) | 3 | None beyond a lost job |
| A8 | The agent runtime executes commands the model wrote | ASI05 | Medium | A restricted tool set: the runtime loads only the tools named on its command line, and the one that runs shell commands is never named. The worker is assumed compromised either way | Built for the fixture run: one tool reached the model. With the tool service, the tool set comes from a recipe and an empty configuration directory, and the service lists only the tools in the job's scope: one tool reached the model in a workstation run. On the worker on 2026-10-20, Goose also offered its own `load_skill`, which no recipe removes and which returns one of two texts bundled in the binary ([#139](https://github.com/sindredg/ai-security-platform/issues/139)). Goose renders the recipe as a template before parsing it, so a task with template syntax could replace the recipe and its extensions: seen with `--render-recipe` and the pinned binary on a workstation. The job program refuses such a task, and one Goose would run as a shell or slash command. Written, with unit tests. Not tested: a model that asks for a tool it was not given. In the model comparison, evidence asked for a tool the model was not given, and none of three models called it ([worklog](../worklogs/0003-toolchain-integration.md#second-run)) | 3 | Code execution on the worker is the starting assumption, not the breach |
